## Commands

```powershell
ruff check backend frontend ml tests
mypy backend/app/models backend/app/core backend/app/schemas backend/app/services --ignore-missing-imports
python -m pytest tests/ -v --cov=backend/app --cov=ml --cov-report=term-missing
python backend/scripts/run_rag_eval.py
python backend/scripts/run_agent_eval.py
```

SQLite migration verification used `alembic upgrade head` against a fresh isolated database and a copy of a prior `create_all()` database. The legacy payment count check was read-only. The 50K verification used the repository generator and canonical ingestion service against a separate migrated SQLite database, then queried the stored payment count independently. During this run, stricter customer ownership checks first rejected all generated rows because the generator had not seeded merchant-scoped customers. The generator now creates merchant-specific customer IDs and seeds those synthetic customers before import; the rerun accepted all 50,000 rows.

The first full-suite attempt used the repository's existing default `backend/data/paybridge.db`, which had not been upgraded to the new anomaly-history columns, and failed six integration tests. That run did not modify the project database. The final suite ran successfully on a disposable, freshly migrated database populated by `backend/scripts/setup_all.py`.

The RAG eval's 18/22 pass score is a known gap. Test results do not establish production readiness, payment-provider success, PCI compliance, or operational reliability under real traffic.
